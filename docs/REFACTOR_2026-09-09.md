# Backend simplification — isolated refactor branch

## Delivery boundary

Branch: `refactor/jobpilot-simplify-20260909`.

The owner explicitly requested on 2026-09-09 that this work remain outside `main`. Commit and push only this branch. Do not merge it into `main`, restart production, or replace the installed Android application without a new instruction.

The original refactor started at `227c2c5` and was preserved in commit `ca3c843`. The five subsequent published commits through `main@1c3ebb3` were then incorporated **into this feature branch**. Current application versions remain Web **0.4.6**, Android **0.3.8/code12**, backend contract **0.3.8**. This is a branch acceptance record, not a production release.

## Changes and preserved behavior

- Profile-scoped candidature storage, tracking updates, saved-offer persistence and report reconciliation now live in `web/src/lib/candidatures.ts`. HTTP and background-task consumers use the service directly rather than routing back through a separately running localhost server.
- Formal evaluation calls `executeTransportEvaluation` directly. Tailored CV uses the current draft-generation service; the model adapter, frozen Candidate evidence, report/PDF persistence checks and task lifecycle remain intact.
- `lib/pipeline-store.mjs` owns the canonical inbox/history writers. Scanner public exports, file formats and locks remain compatible, while saving an offer no longer loads the full scanner/provider engine.
- A failed writer process or empty writer response no longer reports success. A saved-offer operation rereads the candidature store after asynchronous canonical writing before adding its card, preserving other saves made during that wait. Repeated saves reuse the existing card.
- The unreachable generic run dispatcher, detached evaluator, old CLI/PDF-envelope implementation and their exclusive tests were removed. Four unused direct Web dependencies were removed: `@paper-design/shaders-react`, `class-variance-authority`, `clsx`, `tailwind-merge`.

The main-to-feature integration preserved exact-URL report identity, valid zero scores, completed-evaluation card repair, save-before-evaluate, CV drafts/edit/review/accept/reject, the presentation-score floor, display localization, inline AI progress, collapsible interview plans, onboarding/skip-all and hidden user-facing cost metrics. It did not restore the retired execution paths.

No Candidate data migration, new database, authentication change, additional model framework or production service change was required. Applicable MIT/third-party attribution remains unchanged.

## Failures resolved during continuation

The previous cleanup mistakenly removed the `normalizeUrl` import still used by evaluation task validation. Restoring it fixed both recorded `mobile-persistence` failures; the existing tests caught this genuine regression.

The newly integrated save-before-evaluate test used a data-only fixture. Once writer errors became explicit, the missing canonical writer made that test fail. Its fixture now includes the real lightweight writer and asserts both inbox and history persistence, instead of allowing a failed write to look successful.

The AI acceptance scripts still expected generation to overwrite `job.cv`. Their CV assertions now verify the current `job.cvDraft` contract: a real PDF, ATS result, assessment, pending user confirmation and an unchanged previously saved CV.

## Reproduction

From `web/`, using the existing local development dependencies and browsers:

```powershell
npm test
npm run typecheck
npm run build
$env:BUILD_DIST='.next'
$env:JOBPILOT_QA_ENGINE='chromium'
node scripts/qa-jobpilot-web.mjs
npm run qa:backend
$env:JOBPILOT_QA_ENGINE='webkit'
node scripts/qa-jobpilot-web.mjs
npm run qa:backend
```

`qa:backend` starts and stops its own built Next process. It uses fictional local data only and deliberately points the retired self-HTTP address at an unavailable port. It does not submit applications, start production AI tasks or expose a public service. The real-model verifier is separate and requires explicitly configured private model credentials; it is not part of `qa:backend`.

Private evidence remains under ignored `.career-ops-web/refactor/` and `.career-ops-web/mobile-qa/benchmark-20260908/`. Do not publish those directories wholesale.
