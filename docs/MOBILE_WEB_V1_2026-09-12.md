# Onward V1 — Mobile Web Only handoff (2026-09-12)

## 2026-09-13 Intent-first search / Deep-only visible score / active loading states

V1 discovery now follows the product rule **“the user chooses the direction; Onward explains the distance.”** Explicit searches are intent-first: Search Relevance remains dominant, while the candidate's current Fast Fit and a new bounded `bridgeability` signal only refine order inside a relevant pool. Fast Fit no longer contains Search Relevance and now uses the same four conceptual dimensions as Deep Match (`role 30 / duties 30 / tools_languages 20 / level 20`). Seniority/language gaps remain visible fit evidence instead of silently pushing an explicitly requested career direction out of search. `V1_SEARCH_REVISION=v16-intent-first-deep-score` invalidates the older cached Fast-dominant ordering.

Fast Fit is now internal. Home role cards, Opportunities cards, first-run role cards and the Job hero **never use Fast Fit as a temporary user-facing percentage**. The only visible 0–100 role-fit score is Deep Match. Before Deep Match completes, the score position is a small animated shimmer state (`计算中 / Calcul… / Calculating`) with a continuously updated estimated-seconds label. Opening a role that was outside the automatic prefetch group starts a silent Deep Match for that exact role rather than leaving it permanently unrated.

Job Detail no longer looks empty while analysis or presentation work is active. If Deep Match is still running, the Match body shows a large rectangular shimmer/pulse skeleton approximating the final reading area, with `正在计算岗位匹配` and an estimated remaining time. If Deep Match exists but the visible-language translation is still pending, the same surface switches to `正在翻译岗位分析` and an estimated translation time. The Deep score may already be shown in the hero during translation because the score itself does not change with localization. Reduced-motion users receive the same placeholders without animation.

The same Deep-ready boundary now protects role-CV generation for V1 roles. The CV tab stays in the analysis-loading state until Deep Match exists, and the server returns a localized 409 if a stale/direct request tries to generate a role CV before that point. This prevents the internal Fast Fit from becoming the persisted role-CV comparison baseline. Fast-only explanatory strings are no longer sent through display localization because they are no longer rendered.

## 2026-09-13 Application-CV language authority — deployed fa98efe

`求职简历 / CV de candidature / Application CV` is now the sole target-language setting for newly generated role-specific CVs. The choice is intentionally limited to **Français / English**. It is independent from the visible app/analysis language and is not added to job-search criteria. Both first-run upload and Profile explain the same rule: selecting a language only controls future generated CVs; it never narrows the jobs retrieved.

Upload semantics are also separated from output semantics. The browser sends `applicationLanguage`, not a user-declared source language. Extraction detects the uploaded CV language independently where the current detector can do so and stores that only as source provenance (`cv.source_language`); an unknown/other source is recorded as `auto`. Import no longer changes `cv.language` to match the uploaded document, and the selected application-CV language can therefore remain English while the source CV is French/Chinese/another language, or remain French while the source is English/another language.

Role-CV rendering now treats that selected application language as the final document authority. In addition to generated summary/experience/projects/education/skills and the normalized identity header, the finalizer receives every source-layout string that can still survive rendering: headline, contact text, section titles, source-only sections such as languages/interests/other, and footer. A bounded OpenAI direct normalization step translates those visible leftovers into the selected French/English target while preserving section/block geometry, dates, numbers, contact details, language proficiency levels, URLs, entities, tools and factual strength. Source blocks that are actually replaced by generated payload content remain structurally immutable and are not needlessly rewritten. The renderer identity is now `single-column-v7-application-language-authority`, so older saved drafts are re-rendered through the new boundary before preview/download.

The final PDF guard remains strict rather than silently accepting a mixed-language document. For French/English role CVs it now rejects residual Chinese/Japanese/Korean/Cyrillic/Arabic/Hebrew/Thai/Devanagari script, not only Han. The user-facing failure no longer tells the user to “check the material language”; it states that conversion to the selected target language did not finish and invites a retry while preserving the original CV.

## 9-task Mobile Web V1 hardening — code pushed, public rollout pending

The Project OS nine-task development prompt has now been implemented on `feature/v1-mobile-web-only-20260912` in two coherent product commits: **`d7dc9d8`** (`fix(v1): decouple search from progressive enrichment`) and **`b92d37f`** (`fix(v1): tighten mobile opportunity and CV flow`). The four P0 changes are structural rather than copy-only fixes. Search completion is now based on retrieval + Fast Match, not on Deep Match, localization or role-CV generation; a completed search can display immediately while per-offer enrichment continues independently. Starting another search keeps the previous usable offer batch visible. Deep Match no longer pre-generates role CV content. Search history is retained across Candidate Versions and labelled with its CV version; stale-history scores are hidden rather than projected onto the current CV. The six-directions-per-day budget is scoped to the current Candidate Version, and explicit refresh bypasses cache without consuming another direction slot. UI language remains a presentation dimension only; translation operations are segment-addressed, failed/interrupted localization is terminal/retryable, and first-run direction readiness now waits for direction-label localization so the direction screen cannot briefly appear empty.

The CV boundary was also tightened. The exact uploaded original-file contract from `1c7c16c` remains unchanged and its three provenance regressions continue to pass. A generated role CV still targets one A4 page and makes one compact rendering attempt, but a factual CV that remains two or more pages is now preserved as a real reviewable PDF with an explicit length warning instead of failing the whole generation. Contact rendering de-duplicates email/phone/URL pieces, including when one source line contains several contact items. Role-CV uplift is no longer surfaced from a speculative prepared payload: only a real rendered/reviewed draft or accepted role CV may show an actual score change, and `+0` is valid. Manual role-CV edits require an explicit user-provided-facts confirmation before regeneration. Rejecting a role CV can store a reason, and the next generation prompt uses that rejection reason as a constraint.

Job detail now follows one reading line: role requirements → responsibilities → match → evidence/strengths → capability gaps → CV-presentation gaps → next step → original source/apply action. Tracking remains directly reachable from the hero/tabs without a duplicate layer. The CV tab has one generate path rather than duplicate generation/preparation actions. Profile places the original CV card directly below the profile header, removes the redundant CV submenu/statistic, keeps applications/saved roles, and groups location/target-role/contract preferences at one high-level entry. ## Exact original-upload CV viewing — 2026-09-12

The V1 CV contract now separates the **immutable uploaded file** from the **processed Candidate representation**. ## 2026-09-12 Saved-job Match localization no longer re-blocks completed analysis
